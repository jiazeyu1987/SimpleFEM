### 2. 波峰检测逻辑描述差异

#### 原始版（二态简化）

```python
# 简化的二选一逻辑
if hybrid_detection_enabled:
    # 混合检测
    hybrid_peaks = hybrid_peak_detection(
        roi1_gray_buffer,
        gray_buffer,
        config
    )
    green_peaks = [p for p in hybrid_peaks if p['color'] == 'green']
    red_peaks = [p for p in hybrid_peaks if p['color'] == 'red']
else:
    # 传统 ROI2 检测
    green_peaks, red_peaks = detect_peaks(
        gray_buffer,
        threshold,
        ...
    )
```

**特点**:
- 只检查 `hybrid_detection_enabled`
- 简化的二态逻辑（混合 OR ROI2）
- 没有提及ROI1缓冲区状态

#### 重构版（完整三态）

```python
# 完整的三态逻辑（与实际代码一致）
hybrid_enabled = config.hybrid_detection_enabled
roi1_enabled = config.roi1_peak_detection_enabled
roi1_buffer_len = len(roi1_buffer)

# 情况1: 混合检测（ROI1时机 + ROI2颜色）
if hybrid_enabled and roi1_enabled and roi1_buffer_len > 0:
    hybrid_green_peaks, hybrid_red_peaks, hybrid_info = \
        HybridDetectionManager.detect_hybrid_peaks(...)
    green_peaks = hybrid_green_peaks
    red_peaks = hybrid_red_peaks

# 情况2: ROI1数据不足，跳过检测
elif hybrid_enabled and roi1_enabled:
    pass  # 保持空列表，等待ROI1缓冲区积累数据

# 情况3: ROI2独立检测（传统模式）
else:
    green_peaks, red_peaks = detect_peaks(...)
```

**特点**:
- 检查三个条件：`hybrid_enabled`, `roi1_enabled`, `roi1_buffer_len`
- 完整的三态逻辑
- 明确处理ROI1数据不足的中间状态
- **与实际代码实现完全一致**

### 3. 混合检测结果处理差异

#### 原始版

```python
# 步骤 11: 添加到统计
if has_peaks:
    statistics_manager.add_peaks(
        frame_index=frame_index,
        green_peaks=green_peaks,
        red_peaks=red_peaks,
        curve_data=list(gray_buffer),
        ...
    )
```

**问题**:
- 简化的描述，未说明混合检测信息如何传递

#### 重构版

```python
# 步骤8: 添加到统计
if has_peaks:
    # 准备混合检测结果（明确说明）
    hybrid_peaks_for_stats = hybrid_info if (
        hybrid_enabled and roi1_enabled and
        len(roi1_buffer) > 0
    ) else []

    statistics.add_peaks(
        frame_index=frame_index,
        green_peaks=green_peaks,
        red_peaks=red_peaks,
        curve_data=roi2_buffer,
        intersection=intersection,
        roi2_info=roi2_info,
        gray_value=roi2_gray,
        threshold_used=threshold,
        bg_mean=bg_mean,
        roi3_curve=roi3_buffer,
        hybrid_enabled=hybrid_enabled,
        hybrid_peaks=hybrid_peaks_for_stats  # 关键：传递混合检测详细信息
    )
```

**改进**:
- 明确说明了混合检测信息如何准备和传递
- 与实际代码实现一致（这是修复Bug后的关键逻辑）

### 4. 状态机模型差异

#### 原始版

```
阈值保护状态机:
INACTIVE → ACTIVE → INACTIVE
```

**特点**:
- 只有阈值保护状态机
- 简单的三状态转换

#### 重构版

```
1. 阈值保护状态机（扩展版）
   INACTIVE → ACTIVE → RECOVERING → INACTIVE

2. 波峰检测状态机（新增）
   ├── 情况1: 混合检测模式
   │   条件: hybrid_enabled=True AND roi1_enabled=True AND len(roi1_buffer)>0
   │
   ├── 情况2: ROI1数据不足
   │   条件: hybrid_enabled=True AND roi1_enabled=True AND len(roi1_buffer)==0
   │
   └── 情况3: ROI2独立检测模式
       条件: hybrid_enabled=False OR roi1_enabled=False
```

**改进**:
- 增加了 `RECOVERING` 中间状态
- 新增波峰检测状态机，清晰展示三态逻辑
- 每个状态都有明确的触发条件

### 7. 代码示例对比

```python
# 简化的流程伪代码
gray_buffer.append(roi2_gray)
```

```python
# 完整的实际代码逻辑
roi2_gray = self._roi_capture.compute_average_gray(roi2_image)

threshold = self._compute_adaptive_threshold(roi2_gray)

if hybrid_enabled and roi1_enabled and len(roi1_buffer) > 0:

elif hybrid_enabled and roi1_enabled:
    pass  # ROI1数据不足

    green_peaks, red_peaks = detect_peaks(...)
```

**差异**:
- 原始版：伪代码，简化逻辑

### 8. 性能和错误处理

#### 原始版
- 简要提及错误处理
- 基本的性能考虑

#### 重构版
- **三级错误处理策略**:
  ```
  组件级: Manager处理失败 → 降级到默认值
  帧级:   帧处理失败 → 跳过该帧继续
  会话级: 视频处理失败 → 清理资源继续
  ```

- **性能优化细节**:
  - 固定大小缓冲区防止内存泄漏
  - 增量统计算法避免历史数据存储
  - 异步缓存I/O（每50帧刷新）
  - 原子文件写入（临时文件+重命名）

1. **完整反映了代码实现**: 三态逻辑、混合检测结果传递等关键细节
2. **明确了组件边界和职责**: 10个管理器各司其职
3. **提供了更完整的实现参考**: 详细的数据结构、状态机模型
4. **建立了更好的可维护性基础**: 清晰的架构、完整的文档

**最重要的差异**:

| 方面 | 原始版文档 | 重构版文档 | 实际代码 |
|------|-----------|-----------|---------|
| 波峰检测逻辑 | 二态（简化） | 三态（完整） | 三态 |
| ROI1数据不足 | ❌ 未提及 | ✅ 明确说明 | ✅ 已实现 |

因此，**重构版文档与实际代码完全一致**，而原始版文档进行了简化。

这两个文档应该**并存**，各自服务于不同的读者和场景：
