## 问题总结

在重构代码中发现了**两个关键bug**，导致export目录下生成的CSV结果与export2（原始代码）不一致。

## Bug 1: 波峰检测逻辑不完整（已修复）

### 原始代码逻辑（simple_roi_daemon.py 第2216-2334行）

```python

if hybrid_enabled and roi1_enabled and len(roi1_gray_buffer) > 0:
    hybrid_peaks = hybrid_peak_detection(...)
    green_peaks = [p['peak_interval'] for p in hybrid_peaks if p['color'] == 'green']
    red_peaks = [p['peak_interval'] for p in hybrid_peaks if p['color'] == 'red']

# 情况2: ROI1数据不足，跳过检测
elif hybrid_enabled and roi1_enabled:
    # ROI1缓冲区为空，跳过波峰检测（不回退到ROI2）
    green_peaks, red_peaks = [], []

# 情况3: ROI2独立检测
else:
    green_peaks, red_peaks = detect_peaks(...)
```

### 重构代码原始逻辑（错误）

```python
if hybrid_detection_enabled:
```

**问题**: 缺少"情况2"的检查，导致ROI1缓冲区为空时也会调用混合检测。

## 影响分析

### Bug 1 的影响
- 在视频开始时（ROI1缓冲区未满），重构代码会尝试混合检测
- 原始代码会跳过检测，等待ROI1缓冲区积累足够数据
- 可能导致检测时机不一致

### Bug 2 的影响（更严重）
- **混合检测的详细信息（hybrid_peaks）完全丢失**
- 导致CSV中缺失：
  - ROI1波峰ID（roi1_peak_id）
  - 检测方法（detection_method）
  - 波峰质量评分（quality_score）
  - 置信度（confidence）
  - ROI1波峰详细信息

这就是为什么export目录下**少分析波峰**或**波峰信息不完整**的根本原因。

## 修复验证

修复后，重构代码应该：
1. 在ROI1缓冲区为空时跳过检测（与原始代码一致）
2. 正确传递混合检测结果给统计模块
3. 生成与export2完全一致的CSV结果

## 关键要点

1. **波峰检测的三种情况**必须完整实现
2. **混合检测结果**必须传递给统计模块，不能传递空列表
3. 重构时要仔细检查所有数据流，确保关键信息不丢失
